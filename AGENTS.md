# Repository Guidelines

## Project Structure & Module Organization

Dev Toolkit is a client-side SolidJS 1.x application built with TypeScript, Vite, Moraine, and UnoCSS.

- `src/pages/` contains file-based routes. Tool pages are grouped under `(tools)/(encode)`, `(tools)/(json)`, and `(tools)/(utilities)`; `_app.tsx` and `_layout.tsx` define shared shells.
- `src/components/` contains reusable UI and tool-specific components; `src/contexts/` holds shared reactive state.
- `src/utils/` contains conversion, parsing, export, and other tool logic. Tests live beside their implementations.
- `public/` stores static icons, PWA assets, and social images. `vite.pwa.ts` configures offline support; `dist/` is generated build output.
- `src/routes.d.ts` is generated by the router; do not edit it manually.

## Build, Test, and Development Commands

Use the pnpm version pinned in `package.json`; CI uses Node.js 24.

- `pnpm install --frozen-lockfile`: install dependencies from the committed lockfile.
- `pnpm dev`: start the Vite development server.
- `pnpm build`: create the production bundle in `dist/`.
- `pnpm preview`: serve the production build locally.
- `pnpm qa`: run lint autofixes, formatting, and TypeScript checks. This command modifies files; review its diff.
- `pnpm test`: run all tests once.
- `pnpm test:watch`: run tests continuously during development.
- `pnpm test text-case`: run tests matching a filename.

## Coding Style & Naming Conventions

Use two-space indentation, single quotes, and no semicolons, following the shared `@subf/config` presets. Run `pnpm format` (oxfmt) and `pnpm lint` (oxlint). TypeScript uses strict checking.

Use kebab-case filenames, PascalCase components and types, and camelCase functions and variables. Import source modules through `#/` where appropriate. Preserve Solid's reactive patterns and reuse Moraine components, UnoCSS utilities, and `i-lucide-*` icons. New tool routes should provide title, description, category, icon, and tags through `createRoute`.

## Testing Guidelines

NEVER write unit test for components.

Use Vitest and colocated `*.test.ts` files. Utility tests default to Node; component tests opt into jsdom with `// @vitest-environment jsdom` and use Solid Testing Library. Existing property tests use fast-check. Cover changed behavior and relevant edge cases; no numeric coverage threshold is configured.

## Commit & Pull Request Guidelines

History uses short action summaries such as `update table export` and occasional prefixes such as `chore: release`. No uniform Conventional Commits requirement exists. Write specific, concise subjects.

Describe behavior changes, link issues, report checks, and include screenshots for UI changes. Run `pnpm qa`, `pnpm test`, and `pnpm build` before submission.

## Privacy & Configuration

Keep user input processing in the browser and preserve offline behavior. Never commit secrets or local environment files.
